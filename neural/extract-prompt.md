你在给一段很长的聊天记录做预处理。这段记录太长，一次读不完，所以被切成了几段，你只看到其中一段。

你的任务不是写总结，是从这一段里**捞出原始素材**，交给后面的人合并。你捞得准不准，直接决定最终记忆的质量。

# 捞什么

只捞这五类，其他一律不看：

1. **问题**：出了什么错（现象）、为什么（根因）、怎么修的（修法）。三个都要，缺哪个就在那项写「未查出」。
2. **取舍**：选了什么、放弃了什么、为什么。
3. **做法**：能换个场景照样用的具体办法。
4. **他的要求**：他明确说「不要」「必须」的，或者反复纠正同一件事。
5. **交付**：做出了什么东西、放在哪个路径。

# 怎么捞

- **照抄关键字符串**。路径、文件名、命令、报错原文、库名、版本号、参数名，一字不改地抄下来。你一旦改写或「顺手修正」，后面的人就照着错的去查了。
- **不许补全**。这一段的记录里没写根因，就不要写成「大概是因为 X」。写「根因未查出」。
- **不留过程**。中间试错、往返确认、情绪表达，全部丢掉。只留最后成立的东西。
- **每条独立**。不要出现「上面说的那个」「前一段提到的」，把主语和对象写清楚。
- **一句话一条**。一条只讲一件事，别把三个问题塞进一条。

# 特别提醒

- 这一段如果正好是开头，重点看他最初要求做什么、约束是什么。
- 这一段如果正好是结尾，重点看最后成了没有、结论是什么、还剩什么没做完。
- 对话里出现「我」通常指 AI 助手，「你」通常指他本人。写的时候不要照搬人称，直接说事。
- 如果这一段全是寒暄和往返确认，就老实输出「本段无有效素材」，不要编。

# 输出格式

纯文本，每条一行，行首用下面的标签。不要加编号，不要加解释，不要写总结。

问题：现象=…；根因=…；修法=…
取舍：选了…；放弃…；因为…
做法：…
要求：…
交付：…

没有的类别直接不出现，不要写「无」。
